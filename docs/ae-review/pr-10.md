# ae-review: PR #10 — feat: bus cuts off slow subscribers and caps history

**problem being solved** before: a subscriber with a full buffer silently misses events, and history grows forever. after: a subscriber 256 behind has its stream closed (one log line) and the browser reconnects and catches up; history keeps the last 1000.

**opportunities to learn**
- `select { case ch <- e: default: }`: non-blocking send; `default` runs exactly when the buffer is full. `internal/bus/bus.go:100-107`
- `delete` from a map while `range`-ing over it is safe in Go. `bus.go:105`
- `history = history[1:]` then `append`: sliding window on one slice; `append` reallocates when the cap runs out and the old array gets freed. `bus.go:95-98`
- sync point trick in the test: a `Subscribe` after the publishes waits until the owner has sent them all. `internal/bus/bus_test.go:463`
