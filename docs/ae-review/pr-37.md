# ae-review: agent-cli runs the support agent from the terminal (#37)

> PR: [andrelas6/ai-agent-go#37](https://github.com/andrelas6/ai-agent-go/pull/37), `lesson-1-agent-cli` → `main`, 633+ / 198− (code and tests 366+ / 195−). CI green (check, analyze, CodeQL, govulncheck, dependency-review). Reviewed 2026-11-09.

**problem being solved** before: `agent-cli` sends line 1 of stdin plus `claude_hooks.md` to a hard-coded gemma with no tools, dumps one JSON blob, exits 0. after: all of stdin runs through the same support agent and model as the server, one readable line per event, exit 1 on `workflow.failed`.

**opportunities to learn**
- `signal.NotifyContext` installed *after* `readTask`: until `stop`, SIGINT only cancels ctx, so order decides whether Ctrl-C at a prompt exits or hangs. `cmd/agent-cli/main.go:22-28`
- `os.Exit` skips defers, so `stop()` is called by hand before it. `main.go:31-32`
- `io.ReadAll` treats EOF as success: "whole stdin is the task" in 3 lines. `run.go:16`
- `strings.Join(strings.Fields(s), " ")` folds any whitespace run, newlines included, into one space. `format.go:41`
- `json.Compact` with fallback to the raw text on error: invalid model args still print. `format.go:44-50`
- closure over `failed` turns the `emit` callback into the exit-code source; no channel, no return value from `Run` needed. `run.go:28-34`
- table test with `t.Run` per case: a failing event type shows by name. `format_test.go:39-45`

**error handling**
- exit code is "0 unless `workflow.failed` seen". If `Run` ever returns without a terminal event, the CLI exits 0 silently. Fail closed: exit 0 only when `workflow.completed` was seen. `run.go:35-38`
- `fmt.Fprintln(out, …)` error ignored. Fine for stdout (a closed pipe kills the process with SIGPIPE), but a failing `out` in tests would go unnoticed. Low. `run.go:33`
- no `recover` around `Run`, unlike the server's `runSafely` (`handlers.go:118`). A panicking tool prints a Go stack trace and exits 2, not a `workflow.failed` line. OK for a CLI; say so in the plan or add the same guard.

**null handling**
- nothing

**simplicity of the solution**
- `scriptedModel` keeps two parallel slices, `replies` and `errs`, matched by index. One `[]struct{msg agents.Message; err error}` like `fakeReply` in `internal/agents/agent_test.go:46` is easier to read. `run_test.go:13-29`
- `TestFormatEventNeverContainsANewline` passed against the placeholder formatter too, and the fold tests cover the same path. Keep it as a guard or drop it; either is fine. `format_test.go:94`

**naming and language**
- `tool.requested` lines don't show the call id, but `tool.completed`/`tool.failed` lines show only the call id. Pairing them depends on tools running one at a time. Print the id on `tool.requested` too (`tool.requested call-1 classifyItem {…}`), so both lines carry it. `format.go:22`
- `run` (package func) next to `agents.Agent.Run` reads ambiguously in `run.go:29`. `runTask` or `runAgent` says which one.
- `m agents.Model` single letter in a 12-line func is fine; `out` vs `os.Stdout` fine. nothing else.

**how to reproduce**
- before: `git switch main && go run ./cmd/agent-cli < testdata/sample-task.txt` (the file is new in this PR, so before the merge, write the four lines from the course's `SAMPLE_TASK` to a temp file) → `RESPONSE: [...]` about Claude Code hooks, exit 0.
- after: `OPENROUTER_API_KEY=… go run ./cmd/agent-cli < testdata/sample-task.txt; echo $?` → `tool.requested`/`tool.completed` for 3 items, `workflow.completed`, 0. Ctrl-C mid-run → `workflow.failed … context canceled`, 1. `OPENROUTER_API_KEY=` → message, 1.

Agreed in the ae-init ("All of it is replaced", readfile approved), but worth one line in the PR text so the reviewer sees it was on purpose.

**reuse of existing code**
- config lines copied from `cmd/agent-server/main.go:21-25`. Deliberate per plan; note the server's missing-key message (`runner.go:15`) names `-stub`, the CLI's doesn't, so they've already diverged. Fine while there are two callers.
- `scriptedModel` repeats `fakeModel` from `internal/agents/agent_test.go`. Can't import across `_test` packages; accepted.

**code placement**
- nothing

**go concurrency**
- no goroutines. `failed` is written in `emit` without sync, which is correct only because `Agent.Run` calls `emit` in the caller's goroutine (`internal/agents/agent.go:100-245`). That contract isn't written down anywhere. If tools ever run in parallel and emit from goroutines, this becomes a data race. A test or a note on `Run` would pin it down.

**also worth a look**
- PR body says size "366 added"; GitHub shows 633 because of the docs. Fine, but name both numbers to avoid a double take.

## Improvement suggestions

- Exit 0 only when `workflow.completed` was seen, else 1 (`run.go`), plus a test where the fake ends the run with no terminal event — not possible today, so test via a tiny fake `Run`, or skip the test and keep the change.
- Print the call id on `tool.requested` lines, so requests and results pair up without relying on order.
- Fold `scriptedModel`'s `replies`/`errs` into one slice of reply structs.
- Rename `run` to `runTask` (or `runAgent`) to tell it apart from `Agent.Run`.
- Add one line to the PR description: the old `main.go` comments and `readfile.go`'s doc comment were removed on purpose, as agreed in the ae-init.
- Write down, on `Agent.Run` or in the lesson-1 plan, that `emit` is called synchronously. The CLI's exit code depends on it.
- Optional: decide whether the CLI wants the server's `runSafely` panic guard, and record the choice.
